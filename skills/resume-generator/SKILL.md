# 校招简历生成器（模板版）

> 本版本为公开模板：所有 `{占位符}` 需替换为候选人真实信息。**发布/共享前务必删除 `references/事实库.example.md` 与 `references/行业库.md` 中填写的真实个人数据。**

## 内容源优先级（冲突裁决顺序）

1. 用户当前明确给出的新信息或要求
2. `references/事实库.example.md`（唯一事实源，不编造）
3. 本文件硬规则
4. `references/行业库.md` 对应行业章节（要求与表达锚点）
5. 历史简历/旧版本/网络资料（只作参考）

冲突**不自行折中**：会改变责任、成果性质、硬门槛或核心卖点的必须标记并确认；无法确认的优先省略。表达库只能提供措辞，不能创造或修改经历。

## 文件职责

- `references/事实库.example.md` — 经历、数字、责任边界、禁止项（唯一事实源，按示例结构填入候选人真实数据）
- `references/行业库.md` — 互联网/财经/消费 三套选材偏好与表达锚点（按需读取，不同时加载全部）
- `references/reviewer.md` — 独立质检 Reviewer 协议（生成后只读审查）

## 一、事实库核对（先确认再动手）

1. 读取 `references/事实库.example.md`，确认候选人真实数据已完整填入。
2. 若 JD 需要但事实库缺失的信息（关键数字、责任边界、工具使用细节）→ 先深度访谈补齐，用开放问题，不诱导。
3. 候选人提供新经历 → 先更新事实库，再生成；不让旧表达覆盖新信息。

## 二、竞争策略

目标：生成的不是"关键词匹配版简历"，而是**有明确竞争策略的一页说服材料**。核心问题：岗位真正用什么标准筛人 / 为什么该面这个人而不是背景更标准的人 / 哪组真实证据最能支撑。

### Step 1 拆解 JD
内部生成（不必机械照抄给用户）：
- **工作对象**：用户/商家/内容/商品/财务数据/风险规则/供应商…
- **能力定位**：执行/分析/协调/决策/管理的主次
- **核心任务**：入职后最高频 3–5 类真实工作
- **关键产出**：岗位最终交付什么
- **隐含 KPI**：主管真正关心的结果（是推断，须标注）
- **硬门槛与加分项**：学历/专业/语言/证书/工具/实习
- **业务痛点**：3–6 个短语回答"岗位为什么存在"
- **团队文化**：JD 信号 > 官方信息 > 可信外部资料 > 弱推断
- **理想候选人**：最标准录用画像

### Step 2 路由（按工作逻辑，不按公司行业）
- **互联网业务型**：评价用户/商家/内容/商品理解、产品需求/运营/增长、业务指标/数据分析、产品迭代 → 读 `行业库.md` 互联网节
- **财经研究型**：评价行业/公司/政策研究、财务预测/投资判断、尽调/估值/风险/合规 → 读 `行业库.md` 财经节
- **消费业务型**：评价市场/产品/渠道/品牌、消费者洞察、销售/零售运营 → 读 `行业库.md` 消费节

混合岗位选一个主体系，必要时从另一体系借一个具体表达单元，不整套混用。

### Step 3 竞争策略
- 标准候选人是谁？
- 相对位置：直接优势 / 可迁移优势 / 明显缺口 / 不值得暴露的无关缺口
- **Winning Thesis**：一句话回答"为什么该面这个人"，再定 2–3 个 Supporting Signals
- Winning Thesis 不一定写进页眉，用于控制整份简历选材与解释

### Step 4 Evidence Map
为岗位最重要的 3–5 项能力建表（证据全部来自事实库）：

| 岗位能力/任务 | 最强证据 | 次强证据 | 类型(直接/可迁移/弱) | 缺口处理 |
|---|---|---|---|---|

缺口可以省略、弱化、用可迁移能力解释，**不能发明经历**。

### Step 5 匹配度打分（五星制）
- ⭐⭐⭐⭐⭐ 实习直接对口，硬技能完全覆盖
- ⭐⭐⭐⭐ 核心能力匹配，少量短板可简历补齐
- ⭐⭐⭐ 部分匹配，有明显缺口
- ⭐⭐ 匹配度低，建议谨慎投递
- ⭐ 不匹配

**必须在生成简历前向用户输出匹配度评估。**

## 三、简历编写规则

### 基本原则
1. **据实**：不编造经历；数字与责任词都要有出处
2. **用JD原词**：JD写"效果监控"就用"效果监控"
3. **量化结果**：百分比、行数、覆盖量、时间压缩比，每个要点都有数字
4. **删除无关内容**：投游戏岗删B站，投电商岗删游戏，投平台岗删电商
5. **技能按JD结构排列**：JD有"AI工具"条目→技能单独列AI一条

### 简历结构（固定顺序）
```
头部（姓名+联系方式+照片）
教育经历
实习经历（核心实习为主体，4个bullet按JD重新排序和命名）
校园经历
项目经历
技能（4-5条，标题与权重按JD调整）
```

### 实习bullet命名规则
每条标题直接对标JD关键词，不用固定标题：

| JD关键词 | Bullet标题示例 |
|-----------|---------------|
| 效果运营/数据监控 | "数据驱动运营 — 效果监控与异常诊断" |
| 项目管理/全生命周期 | "项目全生命周期管理" |
| AI/自动化/效率 | "AI辅助项目管理与自动化" |
| 产研协同/跨团队 | "流程标准化与产研协同" |
| SOP/流程优化 | "生态管理 — 流程标准化与产研协同" |
| 数据分析/决策 | "数据驱动决策" |

### 表达保护（改写权限分级）
成熟表达是高质量锚点，不是待自动润色的草稿：
- **L0 锁定**：公司、职位、日期、项目标题、数字、成果性质、责任边界、技术能力边界
- **L1 受控**：标签、句序、背景压缩、岗位术语翻译、删次要细节
- **L2 自由**：选哪几个事实组合成bullet、经历排序、技能/课程组合
- **L3 禁止**：创造 JD 关键词对应的虚假经历或结果

仅以下理由可改写成熟句：与岗位解释框架不一致 / 事实冲突或过时 / 信息重复需腾版面 / 理解成本过高 / 句子过长影响扫描 / 有更强且真实的证据。**不得仅因"更简洁""更像AI优化"重写。**一旦保留某段经历，就写到其真实强度上限。

### 技能编写规则
- 每条技能1-2句话，不超过3行
- 技能标题与JD一一对应
- 游戏岗必须加"游戏理解"，电商岗必须加"电商理解与消费者洞察"，内容平台岗必须加"平台理解与内容sense"
- 最后一条统一为"语言与办公"
- 技能栏只补正文尚未证明、但岗位需要的能力，避免纯软件清单

### 多岗位简历合并原则
投同一公司两个岗位时：
1. 识别共同关键词作简历主线
2. 差异化关键词各用一个技能bullet覆盖
3. 实习标题用最宽泛但两JD都能接受的措辞
4. 技能条确保每个JD面试官都能找到自己关心的那条

## 四、生成流程

### Step 1 竞争策略确认
输出匹配度 + Winning Thesis 简述 → 确认投递意向 → 确认第一/第二志愿

### Step 2 生成MD简历
- 保存到 `{输出目录}/个人简历-{公司}{岗位}.md`
- 用HTML style标签包裹CSS（PingFang SC, 12.3px, line-height 1.36）
- 照片用相对路径 `{证件照文件名}.jpg`

### Step 3 生成Python构建脚本
- 保存到 `{输出目录}/build_resume_{shortname}.py`
- 模板参照示例 `build_resume_example.py`
- 照片用base64嵌入HTML
- Chrome headless渲染，A4单页
- 用pypdf验证页数

### Step 4 编译并验证
```bash
cd "{输出目录}" && python3 build_resume_{shortname}.py
```
- 确认输出为1页
- 确认文件大小在合理范围（示例 400-500KB）
- 报出PDF路径

### Step 5 质检Reviewer（独立只读）
读取 `references/reviewer.md`，以只读视角审查竞争策略、证据质量、岗位匹配、表达、ATS与版面，输出 Verdict 与问题清单；不直接改稿。

## 五、质检门禁

- `PASS`：继续最终交付
- `PASS WITH MINOR FIXES`：只做局部修正，不重新生成全文
- `REVISE`：存在 Major 问题，按优先级修订后复核所有 Major
- `REJECT`：存在 Critical（事实/责任/严重岗位错位），先解决再继续

Reviewer 非最高权威：与事实库冲突时事实库优先，与用户明确要求冲突时用户要求优先。主流程对最终修改负责。

## 六、投递文案（可选）

用户要求自荐信、投递邮件、网申自我评价/个人介绍时，基于事实库与本次竞争策略生成：
- 开头一句点出目标岗位与匹配亮点
- 中段 2–3 个最有力证据（对应 Winning Thesis）
- 结尾行动导向（期待面试/附件清单）
- 不重复简历全文，突出简历之外的一句话判断
